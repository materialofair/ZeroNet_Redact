# Cloakmark 1.5.6 (26): release-source provenance

## What this update establishes

This public snapshot synchronizes the retained source copy used for the **1.5.6 (26)** release. The app and share extension in the local Xcode archive created on **2026-10-25 at 15:04:56 UTC** both contain version **1.5.6**, build **26**, and minimum OS **17.6**. The retained upload receipt records a successful App Store Connect upload of that same archive. App Store Connect was read again on 2026-11-07 and shows version 1.5.6 available for distribution with build 26 selected.

The app and extension executable SHA-256 hashes still match the retained release verification:

- App: `19447ecb7c23d75bf0f5447b57742bf4c276d4c2b003344ae30b656f860a703a`
- Share extension: `e719a411dafb93f70da6f8ee4a537a7833de0c8c306c5461461899e12c5dcd07`
- Release project file: `7c3561438542d6985bcb23338673a61f829174346a40478765184690de70ce02`

These are checks of the retained local release materials, not hashes of a downloaded App Store package. Apple can process and re-sign uploaded apps. This is not proof of a reproducible App Store binary or an independent security audit.

## Changes from the previous public snapshot

The base is public main `ac346e6`, including the official website link corrections. All product implementation files already matched the retained release copy. Only two build inputs needed synchronization:

1. `zeroNetRedact/zeroNetRedact.xcodeproj/project.pbxproj`: set marketing version 1.5.6 in all configurations; build remains 26.
2. `zeroNetRedact/scripts/bump-build-number.sh`: use the release fix that validates a common build number but does not mutate the project or products during compilation.

The previous [1.5.5 notes](1.5.5.md) describe the old auto-increment behavior. For 1.5.6, set a new common build number **before** a future Archive. The current script does not reserve or increment it automatically.

Existing public privacy corrections, license notices and product documentation are retained rather than overwritten with older release-copy documents. Internal release notes, upload receipts, signing material, local paths, private media and development history are not added by this sync.

It deliberately excludes generated libraries, signing data and local machine state. It is a maintainer-provided provenance record, not third-party attestation.
