## Automatic video face trajectories and manual covers

`VideoFaceAnalyzer` sequentially decodes video, scales analysis frames to a maximum long edge of 1280, and calls Vision's `VNDetectFaceRectanglesRequest`. Sampling is capped at 30 fps and adapts to duration with a nominal 7200-frame budget and a 2 fps lower sampling target; the code explicitly does not treat that budget as a strict frame limit. `FaceTrackSmoother` associates rectangles by overlap/proximity, smooths their positions and retains briefly missed tracks. This is local geometric association, not identity recognition.

`VideoFaceTimeline.frame(at:)` selects a nearby sampled frame. `VideoCompositionFactory` first renders covers for that frame's automatic face rectangles, selecting effects from any matching person group or the default sticker. It then renders manual regions whose time ranges contain the current composition time. The composition uses a 30 fps time grid; that does not create new detections or continuous motion interpolation between analysis samples.

Manual regions remain at a fixed selected rectangle during the selected interval and can overlay automatic covers. Fast motion, occlusion, missed detections or track mismatches can leave details exposed. These paths establish that automatic trajectories exist, not that tracking is generally reliable. Review complete actual exports before sharing.

## Build from source

On macOS with Xcode and the required iOS SDK:

```sh
git clone --recurse-submodules https://github.com/materialofair/ZeroNet_Redact.git
cd ZeroNet_Redact
# If already cloned without submodules:
git submodule update --init --recursive --depth 1
scripts/build-mupdf.sh
xcodebuild -project zeroNetRedact/zeroNetRedact.xcodeproj \
  -scheme zeroNetRedact -configuration Debug -sdk iphonesimulator \
  -destination 'generic/platform=iOS Simulator' \
  -derivedDataPath /tmp/cloakmark-derived CODE_SIGNING_ALLOWED=NO build
```

MuPDF is pinned at `fe374accd98a43174a328fa7980d7675e06d5b0d` (1.28.2). The build script produces device arm64 and simulator arm64/x86_64 libraries under ignored `third_party/mupdf-build/`. Prebuilt libraries are not committed. See [MuPDF integration](../MUPDF_INTEGRATION.md). For device/archive builds configure your own signing; credentials and provisioning files are not supplied by this repository. Release builds update the project build number as described above.

Geometry tests need no simulator or MuPDF:

```sh
sh scripts/test-editor-geometry.sh
```

Use a dedicated test device/simulator for the app tests. Tests that prepare UI fixtures deliberately import synthetic files; they should not run against a personal or in-use app container.
